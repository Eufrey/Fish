# Step 6C — UI consistency and basic audio

## Setup in the existing Unity Editor

1. Leave Play Mode, refresh assets, and wait for compilation. Preserve any unsaved scene edits.
2. Choose **FISH! > Setup Step 6C UI and Audio**. This creates/reuses `Assets/Resources/FishAudioSettings.asset`, selects it, and applies the shared theme to existing UI in the active scene. Review/save the scene. Repeat on the battle scene if you want its theme saved too; never replace either scene.
3. Assign available clips in the selected settings asset. Repeating setup preserves these assignments. Restart Play after changing clip assignments.
4. No presentation component, camera, AudioListener or EventSystem needs adding. One runtime presentation service supplies audio and the pause UI, reusing the scene's existing Input System EventSystem. Source layout helpers adapt older panels once at runtime, including panels regenerated by earlier setup tools.

**No audio clips were found. All seven slots are intentionally empty:** UI click, fishing success, fishing failure, battle attack, victory, defeat, and looping shoreline ambience. No audio was generated or downloaded. Missing slots are silent and do not prevent play. Matching fish icons/models remain optional as before.

## Controls and scope

- **P** opens Pause / Volume during shore exploration. **Resume**, **P**, or **Escape** closes it. Existing Escape-to-release-cursor behavior outside this menu is unchanged.
- The master slider affects all audio. Only `FISH.MasterVolume` is stored using PlayerPrefs; no catches, HP, team, story or other gameplay data are saved.
- Pause freezes shore time and claims movement/camera/cursor input. It cannot open over fishing, collection, encyclopedia, team, story, or battle. This is a shore pause menu, not a new battle pause feature.
- Existing E/Space/C/N/T/R/F controls and close/cancel/confirmation behavior remain in place. Use the wheel or drag to scroll overflowing text and team content. Primary battle actions and team confirmation/return stay outside scrollable content.

## Changes

- Shared built-in font, tropical panel/button/title palette, distinguishable selection/disabled colors, consistent label padding and 1280x720 Canvas scaling in `FishUITheme.cs`.
- `FishPanelLayout.cs` keeps fishing headings/bar/content/actions separate and gives battle feedback, ability description, actions and outcome buttons distinct rows. Text can scroll without displacing actions. `FishBattleVisuals.cs` reserves space between names, disclaimer and preview.
- `FishTeamLayout.cs` uses balanced columns and expanding long-name rows. `FishTeamPanel.cs` highlights the selected slot and preserves confirmation/edit/recovery feedback. `FishEncyclopediaView.cs` / `FishCollectionPanel.cs` keep collection text scrollable even without a catalog and reset scroll after layout updates; individual names and HP are on separate lines.
- Team, collection, story and pause hints update visibility after input processing so shore HUD cannot flash over a newly opened panel.
- `FishPresentation.cs`, `FishAudioSettings.cs`, `FishButtonSound.cs` and `FishPresentationSetup.cs` supply optional audio slots, a single effects source/shore ambience loop, once-per-frame duplicate-sound protection, and pause volume preferences. Fishing and battle sounds are tied to resolved attempts/actions/results, not every UI refresh; retries reset only the appropriate sound guards.
